# Plan: Kafka Schema Registry + Avro Contract Packages

> **Scope**: Chuyển messaging hiện tại (Confluent.Kafka + JSON) sang **Avro** với **Confluent Schema Registry**, tách contracts thành các **NuGet package per-topic**, enforce backward compatibility, tự động hoá codegen + versioning.
>
> ⚠️ **Scope hiện tại**: **KHÔNG bao gồm CI/CD** để build/publish package. Dev build local qua `pack` (no flags) → local NuGet folder feed; compat check tách riêng qua `check --registry`. CI/CD (Phase 7) sẽ triển khai ở **phase sau** khi có nhu cầu share package giữa team hoặc deploy production.

---

## 1. Decisions

| # | Quyết định |
|---|---|
| Structure | **Monorepo** — đặt tại `api/Shared/Shared.Contracts/` |
| Subject strategy | **TopicNameStrategy** (1 topic = 1 event type) |
| Codegen | **Apache.Avro + avrogen** |
| NuGet feed | **Local folder feed** (`nupkgs/`) cho dev — scope hiện tại; GitHub Packages sẽ setup ở phase CI/CD sau |
| Compatibility | **BACKWARD** |
| Metadata | **Convention-derived** topic + package từ folder/filename; `schemas/topics.json` là build artifact (packageId ↔ topic ↔ version) cho register/CI consumers |
| Tooling | **Project-based** `Contracts.Tools` console + `System.CommandLine` |
| Versioning | **Schema Registry version làm minor** — không dùng git tag, không dùng file manifest |
| Package scope | **1 topic = 1 NuGet package**, tên derive từ topic |
| Generated artifacts | `packages/` và `nupkgs/` **không commit** — chỉ schemas + tools |

## 3. Conventions

### 3.1 Derivation rule — filename + folder → topic + package

Topic và package ID **derive từ path** lúc build, không có metadata field nào trong `.avsc`. Quy tắc:

```
file path  = schemas/<domain>/v<N>/<EventName>.avsc        # domain singular, EventName PascalCase
event_kebab = kebab(EventName), strip leading word nếu == domain (case-insensitive, single segment)
topic       = <domain>.<event_kebab>.v<N>
packageId   = OrderMgmt.Contracts.<Pascal(domain)>.<EventStripped>.V<N>
```

Strip-prefix chỉ áp dụng khi PascalCase split của EventName có > 1 word VÀ word đầu == domain. Đảm bảo class generated giữ tên cũ (`OrderPlaced`, `ProductCreated`).

| File path | Avro `name` | Topic | Package ID |
|---|---|---|---|
| `schemas/order/v1/OrderPlaced.avsc` | `OrderPlaced` | `order.placed.v1` | `OrderMgmt.Contracts.Order.Placed.V1` |
| `schemas/order/v1/OrderCancelled.avsc` | `OrderCancelled` | `order.cancelled.v1` | `OrderMgmt.Contracts.Order.Cancelled.V1` |
| `schemas/catalog/v1/ProductCreated.avsc` | `ProductCreated` | `catalog.product-created.v1` | `OrderMgmt.Contracts.Catalog.ProductCreated.V1` |
| `schemas/catalog/v1/ProductDeleted.avsc` | `ProductDeleted` | `catalog.product-deleted.v1` | `OrderMgmt.Contracts.Catalog.ProductDeleted.V1` |
| `schemas/catalog/v1/ProductRenamed.avsc` | `ProductRenamed` | `catalog.product-renamed.v1` | `OrderMgmt.Contracts.Catalog.ProductRenamed.V1` |
| `schemas/inventory/v1/StockReserved.avsc` | `StockReserved` | `inventory.stock-reserved.v1` | `OrderMgmt.Contracts.Inventory.StockReserved.V1` |
| `schemas/inventory/v1/StockReservationFailed.avsc` | `StockReservationFailed` | `inventory.stock-reservation-failed.v1` | `OrderMgmt.Contracts.Inventory.StockReservationFailed.V1` |

`.avsc` giữ pure Avro spec — không có custom field:
```json
{
  "type": "record",
  "name": "OrderPlaced",
  "namespace": "Com.OrderMgmt.Order.V1",
  "fields": [ ... ]
}
```

**Invariants** enforced trong `SchemaDiscovery` (fail-fast trong mọi command):
- File phải nằm `schemas/<domain>/v<N>/<EventName>.avsc` — trừ root `schemas/topics.json`
- domain folder name == lowercase đầu segment của Avro `namespace` (sanity check tên class)
- Hai file khác nhau không được derive ra cùng topic / packageId

### 3.2 Build manifest — `schemas/topics.json`

File này là **output của `pack`** (không phải input để derive). Generated mỗi lần build, committed để CI/deploy consumers + register tool có một index ổn định của tất cả packages đã build:

```json
[
  { "packageId": "OrderMgmt.Contracts.Order.Placed.V1",                   "topic": "order.placed.v1",                   "version": "1.3.0" },
  { "packageId": "OrderMgmt.Contracts.Order.Cancelled.V1",                "topic": "order.cancelled.v1",                "version": "1.3.0" },
  { "packageId": "OrderMgmt.Contracts.Catalog.ProductCreated.V1",         "topic": "catalog.product-created.v1",        "version": "1.2.0" },
  { "packageId": "OrderMgmt.Contracts.Catalog.ProductDeleted.V1",         "topic": "catalog.product-deleted.v1",        "version": "1.2.0" },
  { "packageId": "OrderMgmt.Contracts.Catalog.ProductRenamed.V1",         "topic": "catalog.product-renamed.v1",        "version": "1.1.0" },
  { "packageId": "OrderMgmt.Contracts.Inventory.StockReserved.V1",        "topic": "inventory.stock-reserved.v1",       "version": "1.1.0" },
  { "packageId": "OrderMgmt.Contracts.Inventory.StockReservationFailed.V1","topic": "inventory.stock-reservation-failed.v1","version": "1.1.0" }
]
```

Vai trò:
- **`register` đọc** để biết subject (`<topic>-value`) và version cần upload — không cần re-derive
- **CD pipeline** đọc để pin `PackageReference` versions cho services downstream
- **Diff trên PR** giúp reviewer thấy version nào tăng / package nào mới mà không cần đọc commit history

Vai trò KHÔNG có:
- ❌ Drive build (`pack` derive trực tiếp từ path, manifest chỉ ghi sau)
- ❌ Source of truth cho topic mapping (topic là derived field, manifest chỉ snapshot lại)

Khi `pack` chạy, regenerate file → nếu diff với committed version: print warning + stage update. CI có thể fail nếu file không up-to-date với commit (`git diff --exit-code schemas/topics.json` sau pack).

### 3.3 Subject (TopicNameStrategy)
```
order.placed.v1-value
catalog.product-created.v1-value
inventory.stock-reserved.v1-value
```

### 3.4 Versioning
```
package version = 1.<registry-version>.<patch>
                  │        │              │
                  │        │              └── 0 (hoặc CI run number cho rebuild uniqueness)
                  │        └── Schema Registry subject version (tăng khi register compatible)
                  └── pinned 1 (BACKWARD compat → major không bao giờ bump trong cùng package;
                                breaking change → package mới `.V<n+1>`)
```

Topic version (`.V<n>`) **không** ở trong semver — nó nằm trong **package ID**. Hai topic versions = hai packages khác nhau, có thể coexist trong cùng service.

| Action | Registry version | Package ID | Package version |
|---|---|---|---|
| Register lần đầu `schemas/order/v1/OrderPlaced.avsc` (derive topic `order.placed.v1`) | 1 | `OrderMgmt.Contracts.Order.Placed.V1` | `1.1.0` |
| Thêm optional field → register → compat OK | 2 | `OrderMgmt.Contracts.Order.Placed.V1` | `1.2.0` |
| Fix description → register → compat OK | 3 | `OrderMgmt.Contracts.Order.Placed.V1` | `1.3.0` |
| Breaking change → tạo `schemas/order/v2/OrderPlaced.avsc` (derive topic `order.placed.v2`) | Subject mới = 1 | `OrderMgmt.Contracts.Order.Placed.V2` | `1.1.0` |

### 3.5 BACKWARD compat rules
| Change | Allowed |
|---|---|
| Add field có `default` | ✅ minor bump (registry tăng) |
| Remove field có `default` | ✅ minor bump |
| Fix doc/description | ✅ minor bump |
| Rename field / type change / add required | ❌ bắt buộc tạo folder `vN+1` + topic `vN+1` |

### 3.6 Required fields (enforced bởi `SchemaValidator`)

Mọi `.avsc` **bắt buộc** có 2 fields:
| Field | Type | Mục đích |
|---|---|---|
| `eventId` | `{ "type": "string", "logicalType": "uuid" }` | Idempotency key cho consumer |
| `occurredOn` | `{ "type": "long", "logicalType": "timestamp-micros" }` | Timestamp event xảy ra |

`pack` fail ngay nếu schema thiếu 1 trong 2.

### 3.7 Shared types giữa schemas

Các types dùng chung (vd. `OrderLineItem` dùng trong `OrderPlaced` + `OrderCancelled`) → **inline trong mỗi `.avsc`**.

**Lý do chọn inline**:
- 1 `.avsc` = 1 package self-contained, không dependency giữa schemas
- Avrogen sinh class độc lập, không cần merge schemas phức tạp
- Trade-off chấp nhận: duplicate class `OrderLineItem` trong mỗi package (khác namespace) — không lớn

**KHÔNG dùng**:
- Avro named-type references cross-file (vd. `"type": "OrderLineItem"` trỏ sang file khác) — tooling phải merge trước khi avrogen, phức tạp
- Package chung "Contracts.Shared" chứa types dùng chung — gây coupling ngược với triết lý per-topic

Registry URL override: CLI truyền `--registry <url>` → set env var `SCHEMA_REGISTRY_URL` trước khi build host, hoặc dùng `IOptionsMonitor<RegistryOptions>` với typed-configure.

**Commands** — single-responsibility split. `pack` không bao giờ touch registry để write; compat check + register là việc của `check` / `register`.

| Command | Flags | Network | Mô tả |
|---|---|---|---|
| `pack` | `--version <semver>` \| `--registry <url>` (read-only lookup) \| `--output <dir>` | optional read | Validate → avrogen → render csproj → `dotnet pack`. Pure local nếu không truyền `--registry`. |
| `check` | `--registry <url>` | read | Compat check `.avsc` chống `latest` subject. Fail nếu incompat. Không write. |
| `register` | `--registry <url>` | write | Upload `.avsc` lên registry (idempotent). Fail nếu incompat. Trả về version. |
| `install-local` | `[--service <name>]` | none | `pack` (local version) + clear NuGet cache + restore service. |

**`pack` flow** — derive everything from path; ghi `topics.json` ở cuối:
```
discovered = SchemaDiscovery.Walk(schemasRoot)   # liệt kê (avscPath, domain, eventName, vN); fail nếu path layout sai
built = []

for each (avscPath, domain, eventName, vN) in discovered:
  1. SchemaValidator.Validate(avscPath)            # eventId + occurredOn
  2. (topic, packageId) = PackageNaming.Derive(domain, eventName, vN)
                                                   # vd. ("order", "OrderPlaced", 1)
                                                   #   → ("order.placed.v1", "OrderMgmt.Contracts.Order.Placed.V1")
  3. version = ResolveVersion(--version, --registry):
        --version <semver>  → dùng nguyên (CI-controlled)
        --registry <url>    → read-only GET /subjects/<topic>-value/versions
                              version = "1.<max(versions)>.0"
                              (subject chưa tồn tại → "1.0.0")
        không gì hết        → "1.0.0-dev.<yyyyMMddHHmmss>"
  4. Temp dir .tmp-build/<packageId>/
  5. Render csproj từ template
  6. avrogen -s schema.avsc Generated/
  7. dotnet pack -p:Version=<version> -o ./nupkgs
  8. Xoá temp
  9. built += { packageId, topic, version }

# Sau khi build xong tất cả packages
BuildManifest.Write(schemasRoot/"topics.json", built)
```

`SchemaDiscovery.Walk` enforce: file phải nằm `schemas/<domain>/v<N>/<EventName>.avsc`, không có file orphan ngoài layout. Hai entries cùng topic / packageId → fail.

**`check` flow** — fail-fast, read-only:

**`Services/PackageNaming.cs`** — derivation rule (single source of truth, pure function):
```csharp
using System.Text.RegularExpressions;

namespace Contracts.Tools.Services;

public static class PackageNaming
{
    public static (string Topic, string PackageId) Derive(string domain, string eventName, int vN)
    {
        // domain "order", eventName "OrderPlaced", vN 1
        //   → topic "order.placed.v1", package "OrderMgmt.Contracts.Order.Placed.V1"
        var stripped = StripDomainPrefix(eventName, domain);   // "OrderPlaced" + "order" → "Placed"
        var topic    = $"{domain}.{ToKebab(stripped)}.v{vN}";
        var package  = $"OrderMgmt.Contracts.{Capitalize(domain)}.{stripped}.V{vN}";
        return (topic, package);
    }

    public static string ToAvscPath(string packageId, string schemasRoot)
    {
        // "OrderMgmt.Contracts.Order.Placed.V1" → schemas/order/v1/OrderPlaced.avsc
        var parts = packageId.Split('.');
        if (parts.Length < 5 || parts[0] != "OrderMgmt" || parts[1] != "Contracts")
            throw new ArgumentException($"invalid packageId: {packageId}");
        var domain  = parts[2].ToLowerInvariant();
        var middle  = string.Concat(parts.Skip(3).SkipLast(1));   // "Placed" or "ProductCreated"
        var vN      = int.Parse(parts[^1].TrimStart('V'));
        // reverse strip: nếu middle là 1 word PascalCase → prepend domain pascal
        var fileName = SplitPascal(middle).Length == 1
            ? Capitalize(domain) + middle
            : middle;
        return Path.Combine(schemasRoot, domain, $"v{vN}", $"{fileName}.avsc");
    }

    static string StripDomainPrefix(string eventName, string domain)
    {
        var words = SplitPascal(eventName);
        return words.Length > 1 && string.Equals(words[0], domain, StringComparison.OrdinalIgnoreCase)
            ? string.Concat(words[1..])
            : eventName;
    }

    static string[] SplitPascal(string s) =>
        Regex.Matches(s, @"[A-Z][a-z0-9]*").Select(m => m.Value).ToArray();

    static string ToKebab(string pascal) =>
        string.Join('-', SplitPascal(pascal).Select(w => w.ToLowerInvariant()));

    static string Capitalize(string s) =>
        s.Length == 0 ? s : char.ToUpper(s[0]) + s[1..];
}
```

**`Services/SchemaDiscovery.cs`** — walk `schemas/`, parse path layout, fail nếu không match `<domain>/v<N>/<Event>.avsc`:
```csharp
using System.Text.RegularExpressions;

namespace Contracts.Tools.Services;

public sealed record DiscoveredSchema(string AvscPath, string RelativePath, string Domain, string EventName, int V);

public static class SchemaDiscovery
{
    private static readonly Regex Layout = new(@"^(?<domain>[a-z][a-z0-9-]*)/v(?<n>\d+)/(?<event>[A-Z][A-Za-z0-9]*)\.avsc$");

    public static IReadOnlyList<DiscoveredSchema> Walk(string schemasRoot)
    {
        var results = new List<DiscoveredSchema>();
        var seenTopics = new HashSet<string>();

        foreach (var path in Directory.EnumerateFiles(schemasRoot, "*.avsc", SearchOption.AllDirectories))
        {
            var rel = Path.GetRelativePath(schemasRoot, path).Replace('\\', '/');
            var m = Layout.Match(rel);
            if (!m.Success)
                throw new InvalidSchemaException(path, $"path '{rel}' must match <domain>/v<N>/<Event>.avsc");

            var schema = new DiscoveredSchema(
                AvscPath:     path,
                RelativePath: rel,
                Domain:       m.Groups["domain"].Value,
                EventName:    m.Groups["event"].Value,
                V:            int.Parse(m.Groups["n"].Value));

            var (topic, _) = PackageNaming.Derive(schema.Domain, schema.EventName, schema.V);
            if (!seenTopics.Add(topic))
                throw new InvalidSchemaException(path, $"duplicate derived topic: {topic}");

            results.Add(schema);
        }

        return results;
    }
}
```

**`Services/SchemaValidator.cs`** — enforce required fields trong từng `.avsc`:
```csharp
using System.Text.Json;

namespace Contracts.Tools.Services;

public static class SchemaValidator
{
    public static void Validate(string avscPath)
    {
        var root = JsonDocument.Parse(File.ReadAllText(avscPath)).RootElement;

        if (!root.TryGetProperty("fields", out var fields) || fields.ValueKind != JsonValueKind.Array)
            throw new InvalidSchemaException(avscPath, "missing 'fields' array");

        var fieldNames = fields.EnumerateArray()
            .Select(f => f.GetProperty("name").GetString())
            .ToHashSet(StringComparer.OrdinalIgnoreCase);

        if (!fieldNames.Contains("eventId"))
            throw new InvalidSchemaException(avscPath,
                "missing required field 'eventId' (string, logicalType=uuid)");

        if (!fieldNames.Contains("occurredOn"))
            throw new InvalidSchemaException(avscPath,
                "missing required field 'occurredOn' (long, logicalType=timestamp-micros)");
    }
}

public sealed class InvalidSchemaException(string path, string reason)
    : Exception($"Invalid schema {path}: {reason}");
```

Pipeline order trong mọi command:
- `pack` / `check`: `SchemaDiscovery.Walk(schemasRoot)` → fail nếu path layout sai / topic duplicate; cho từng schema gọi `SchemaValidator.Validate(avscPath)` rồi `PackageNaming.Derive(...)`.
- `register`: `BuildManifest.Read(schemas/topics.json)` (CI flow chuẩn — pack đã chạy trước) hoặc walk + derive nếu manifest chưa có; cho từng entry, `PackageNaming.ToAvscPath(packageId, schemasRoot)` để lấy bytes upload.

**`Services/RegistryVersioning.cs`** — wrap Refit interface, mỗi method 1 responsibility (mapping 1-1 với 3 commands):
```csharp
using System.Net;
using Refit;

namespace Contracts.Tools.Services;

public sealed class RegistryVersioning
{
    private readonly ISchemaRegistryApi _api;

    public RegistryVersioning(ISchemaRegistryApi api) => _api = api;

    // Dùng bởi `check` — read-only, throw nếu incompat
    public async Task CheckCompatAsync(string subject, string avscJson, CancellationToken ct = default)
    {
        var resp = await _api.CheckCompatibilityAsync(subject, new SchemaPayload(avscJson), ct);
        if (resp.StatusCode == HttpStatusCode.NotFound) return;   // subject mới → pass
        if (!resp.IsSuccessStatusCode)
            throw resp.Error ?? new Exception("Compat check failed");
        if (!resp.Content!.IsCompatible)
            throw new IncompatibleSchemaException(subject, resp.Content.Messages ?? []);
    }

    // Dùng bởi `register` — idempotent write, trả về version sau khi register
    public async Task<int> RegisterAsync(string subject, string avscJson, CancellationToken ct = default)
    {
        await _api.RegisterAsync(subject, new SchemaPayload(avscJson), ct);
        var versions = await _api.GetVersionsAsync(subject, ct);
        return versions.Max();
    }

    // Dùng bởi `pack --registry` — read-only lookup để compute next version
    public async Task<int> GetLatestVersionAsync(string subject, CancellationToken ct = default)
    {
        try
        {
            var versions = await _api.GetVersionsAsync(subject, ct);
            return versions.Length == 0 ? 0 : versions.Max();
        }
        catch (ApiException ex) when (ex.StatusCode == HttpStatusCode.NotFound)
        {
            return 0;   // subject chưa tồn tại
        }
    }
}

public sealed class IncompatibleSchemaException(string subject, string[] messages)
    : Exception($"Schema {subject} incompatible: {string.Join("; ", messages)}");
```

- `AddStandardResilienceHandler()` plug thẳng vào — retry + circuit breaker miễn phí
- Serialization qua `SystemTextJsonContentSerializer` với camelCase policy — khớp Schema Registry REST spec

```csharp
        this IServiceCollection services, IConfiguration config)

        return services;
    }

        services.AddHostedService(sp =>
            ActivatorUtilities.CreateInstance<KafkaConsumerHost<TEvent>>(sp, topic));

    }
```

### ⚠️ Risk: `pack` mặc định không gọi compat check

`pack` chỉ build — compat check là job tách của `check`. Dev có thể vô tình break BACKWARD nếu skip step `check`, không phát hiện cho đến production (hoặc tới khi Phase 7 CI bắt được).

**Best practices** khi chưa có CI:
1. Trước khi push PR → `docker compose up -d schema-registry` + `dotnet contracts-cli check --registry http://localhost:8085`
2. Set up **pre-commit git hook** (`.githooks/pre-commit`) chạy `check --registry` nếu có file `.avsc` trong staged changes
3. Code review tay: reviewer đọc kỹ diff `.avsc`, xác nhận nằm trong BACKWARD allowed changes (xem table 3.5)

Khi Phase 7 CI sẵn sàng, risk này tự động giải quyết vì PR bắt buộc pass `check --registry`.

## 6. Versioning & CI/CD flow

`pack` luôn deterministic — same `.avsc` + same `--version` → bit-identical `.nupkg`. Version đến từ flag, không phải side-effect của registry.

| Scenario | Commands | Version format |
|---|---|---|
| **Local dev (inner loop)** | `pack` | `<major>.0.0-dev.<timestamp>` |
| **PR preview (CI)** | `check --registry <ci>` → `pack --version <major>.<V+1>.0-pr.<runNumber>` | `1.3.0-pr.42` |
| **Main production (CI)** | `register --registry <prod>` (returns V) → `pack --version <major>.<V>.0` | `1.3.0` |
| **Lookup-then-pack (one-shot)** | `pack --registry <prod>` (read-only query) | `<major>.<V>.0` |

Tách responsibilities:
- `pack` — build only, không touch registry để write. Reproducible.
- `check` — fail-fast trên PR, không write.
- `register` — chỉ chạy sau khi merge main, side-effecting nhưng idempotent.
